Behind the Seduh

Same brand. A different build — told one phase at a time.

This is the rebuild, not the pitch. Seduh Score Next is what happens when the guy who built the original Seduh Score decides the receipt-and-group-chat problem deserved a second draft — offline-first this time, a real database instead of Firebase shortcuts, and a fixed advancement bug the old app never quite trusted itself with.

One phase at a time, aimed at a real deadline: the Cup Tasters event on 4 October 2026.

How we're naming this one

The version standings

The legacy site named its versions after Bruneian places, spreading out from the capital — Kiulap through Seria, v1.0 through v5.x (seduhscore.com/bts/). This build keeps that same place order and direction — deliberately — without continuing that run itself. Read top to bottom, most recent first, same as any standings table.

The build, phase by phase

What shipped — and what it felt like.

Kiulap — seven phases per the project's frozen handoff spec, all shipped. Then Berakas — a front door nobody had planned for, jumping the queue.

Phase 0
Foundation
ShippedThe scaffold, nine review subagents, four custom ESLint rules, a local Supabase stack wired into CI, and a protected main branch.
Felt likewriting down the rules before writing any of the code they'd police.
Phase 1
Schema & security
ShippedEvery core and Cup Taster table, row-level security across all thirteen of them, and a dedicated pgTAP gate proving every write policy carries a real WITH CHECK.
Felt likefinding a live cross-org bug in review before it ever reached a real event.
Phase 2
Core libraries
ShippedPartitioning, ranking, advancement, countdown, time-clamping, and entitlements — pure logic, fuzz-tested against thousands of combinations before a single screen existed.
Felt likepaying down the old app's advancement bug before it could be reborn here.
Phase 3
Registry & offline
ShippedPerson/entry registration with real dedup, an IndexedDB mirror, and a FIFO outbox queue with idempotency keys — the spine every later screen writes through.
Felt likedesigning for the wifi at the venue, not the wifi in the office.
Phase 4
Cup Taster
ShippedStage setup, roster, heat generation, live timing, the three-state scoring toggle, standings with a real tiebreak flow, a completion report, and export — the format's full loop.
Felt like"correct is a count, never a column" stopping being a rule on paper and becoming a real constraint.
Phase 5
Live surfaces
ShippedA publish path, a shared viewer shell over Supabase Realtime, and two real consumers — projector and phone — proven to agree on the same countdown, to the second.
Felt likethe point this stopped being an organiser tool and became something a whole room could watch at once.
Phase 6
Hardening
ShippedAccessibility pass, offline soak testing, and a dry run against the real roster — local and production both green. Guess the Bean stayed the working v4.x version, deliberately not rebuilt.
Felt likethe unglamorous work that decides whether October 4th actually goes well — closed out before the event ever started.
Berakas
The public front door v2.0.0 Current cycle
ShippedThe public marketing landing page — out of the original handoff's scope entirely, shipped because it was needed. The console moved to /app/ to make room for it; this page you're reading now lives right alongside it.
Felt likethe moment this stopped being a private rebuild and got an actual public front door — the same thing legacy's own Berakas cycle was, for the same reason.
