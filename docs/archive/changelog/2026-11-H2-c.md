## Seduh ID Layer 2, B3a: the claim backend (issue, redeem, #0001) · 2026-11-18

**Task:** T-ID2.B3a. Branch `claude/l2-b3a-claim-backend-58f386`, PR into `dev`. Migration `20261118100000_seduh_claim.sql`, Edge Function `seduh-claim` (new), pgTAP `082` (new) and `037`, `041`, `050`, `062`, `079` updated. **Patch bump to 4.10.7** (groundwork nobody can use yet: no screen reaches it until B3b). **Not pushed to the cloud; the function is not deployed.**

- **Issue (organiser):** `issue_seduh_claim_link(person)` returns the raw 256-bit token once and stores only its SHA-256 (72 hours); org derived from the person, then `refuse_non_member`; revokes every open link first (expired ones included). `revoke_seduh_claim_link(person)`; `seduh_claim_statuses(org, persons[])` for the People screen. Hints for no identity (an opted-out identity answers the same, so nobody learns who objected), merged, already claimed.
- **Redeem (competitor):** Edge Function `seduh-claim` checks the token FIRST (`seduh_claim_begin`, service role only, six emailed codes per link), then finds or creates the login with the service role and has Auth email a 6-digit code (`shouldCreateUser: false`); the page verifies the code in the browser and calls `claim_seduh_id(token, handle, adult)`. Refusals with hints: reserved, malformed or taken handle; used, revoked or expired link; claimed identity; a login that already has an account; a platform-admin login; `p_adult` not true. `seduh_handle_available(handle)` for the claim page (anon).
- **#0001:** `app.seduh_reserved_numbers` (only the number 1, one identity); `claim_seduh_id` passes the number explicitly and sets `app.seduh_owner_assignment` for that insert only when the claiming identity holds the reservation. Full owner path and the undo-a-claim runbook are in `CONVENTIONS.md` ("Seduh ID claim").
- **Audit:** `app.seduh_claim_audit` (own table: the admin audit log is admin-gated and pinned by `047`), append-only, no token, email or phone.
- **Local config:** the Magic Link email now carries the code (`supabase/templates/magic_link.html`, link kept so Guess the Bean is unchanged); the cloud template must be edited by hand. Local `email_sent` raised 2 to 100.
- **Decisions the spec left open and flagged:** see the PR body. Notably: the cloud's email signup is probably already on (Guess the Bean needs it); an undone claim leaves its identity unclaimable (A2's unique `identity_id`); display name is returned to a token holder.
- **Reviews:** `security-reviewer`: no 🔴; two nits (links are identity-wide across two organisations: documented as accepted, `DECISION C2`; the six-code cap is spent before the send: commented), plus test gaps. `schema-guardian`: no 🔴; nits: the unique-violation handler mislabelled a founding-number clash as `handle_taken` (fixed: it now tests the constraint name and re-raises anything else; also found by `code-reviewer`), a TRUNCATE cascade can clear a consumed reservation (comment softened, same owner-only limit as A2), `079` prints a plan-count diag after the savepoint (harmless, PASS). `code-reviewer`: one 🔴 (prettier failed on `CONVENTIONS.md` and the template: fixed) and five doc and consistency nits (fixed). `test-auditor`: two 🔴 by 35 mutation runs (the claim response was never checked for the token or its key set; two e2e negatives could not fail), fixed, plus four nits fixed (a refused begin counts no code, expired-open link status, relabelled anon line, 8 parallel claims in the e2e). The independent fresh-context check of each 🔴 was the auditor's own re-execution of the mutants, and the format failure reproduces by `prettier --check`; no separate checker agent was run. One round, no 🔴 left. `079` asserts whole-table counts, so it fails on a local database that has run the claim e2e until `npm run db:reset` (CI runs pgTAP first on a fresh database).

## Seduh ID Layer 2, B1: the profile door `public_seduh_profile(handle)` · 2026-11-16

**Task:** T-ID2.B1. Branch `claude/l2-b1-profile-door-b6d900`, PR into `dev`. Migration `20261116100000_public_seduh_profile.sql`, pgTAP `080`. **Patch bump to 4.10.5** (database only: a door with no page behind it yet). **Not pushed to the cloud.**

- **What:** the one anonymous door behind `/id/<handle>/` (`SECURITY DEFINER`, `STABLE`, empty `search_path`, `anon` and `authenticated`). It applies a claimed person's privacy settings in SQL and returns one stable JSON object (contract in `CONVENTIONS.md`, "Seduh ID profile door"). Every figure is derived on read; nothing is stored. A claimed page with every part hidden still returns its handle (`has_profile` true); every other input (unknown, closed, merged, opted out, reserved, malformed, NULL) gets one identical empty shape.
- **Core invariant:** a profile never shows a result `/results/` does not show. Results are read from the published `public_results` payload (standings, else podium) of non-test events, matched to a person by the archive feed's name-and-cafe rule; nothing is read from the live scoring tables for a result.
- **Formats:** Cup Taster returns results. Throwdown returns nothing: `knockout_record` is always zeros until Throwdown publishes a results payload (owner decision, see below). BTC returns nothing (teams and judges have no person link). Seams, empty and named for their phase: `photo_url` (C2), `organiser_records` and `self_reported` (C), `judging_roles` (needs a judge link), `cafe_affiliations` (two-sided acceptance), `is_shadow` (flag does not exist yet).
- **Owner decisions flagged:** (1) Throwdown knockout: the first draft read the live match tables for a published event (beyond `/results/`, gate easy to satisfy); **decided: nothing until Throwdown publishes a payload**, so the read was removed and `080` pins zeros; (2) the identity link is organiser-asserted, so a published result can land on a stranger's page labelled `seduh_score`: **accepted as built**; the Phase C answer is a "This isn't mine" report on the profile (the planning session adds it to the spec; no code here). Both in `CONVENTIONS.md`.
- **Reviews:**
  - `schema-guardian`: clean (rollback run in a transaction, ACL, indexes).
  - `code-reviewer`: one finding, fixed: an impossible payload date (`2026-02-30`) passed the shape check and made the door raise; the date now comes from the event row.
  - `security-reviewer`: no leak found. Two design findings, put to the owner: the Throwdown read widening (fixed: the read was removed, re-reviewed below) and the organiser-asserted link (accepted as built; "This isn't mine" report in Phase C). Two nits fixed: a podium row no longer shows a round or time, and a score needs both figures.
  - `security-reviewer`, second pass on the knockout removal only: clean (no `td_*` read left, shape unchanged).
  - `test-auditor`: no 🔴; 29 of 37 mutants killed. Gaps closed by new fixtures: closed, merged, opted-out and identity-hidden opponents, pool and level matches, wrong-cafe and duplicate-row results, a partial score. Not covered: the `limit 10` on opponents, a missing settings row, the payload-versus-live event name.
  - Guard `062` (functions touching the identity tables) needed the new door added: done.
- **Guards:** `037` door list, `080` (door shape, privileges, no table access, every visibility setting, results from two organisations, unpublished/test/duplicate/renamed/BTC exclusions, knockout counts and opponent naming, identical empty shapes, JSON text scan for phone, email and uuid). `041` needs no entry (the door takes text).
