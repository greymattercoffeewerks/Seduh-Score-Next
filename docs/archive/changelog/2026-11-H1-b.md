## v4.5.0: BTC scores CSV, two downloads on the Records card (Organiser UX U4, Q10 proposal) · 2026-11-11

**Task:** Organiser UX U4, the CSV half of the records card (spec section 6, Q10). No migration, no cloud change, no `core/` change. **Not final:** the owner has not yet shown the proposal to the committee, and the test-auditor re-check of its two fixes is not recorded (see Reviews).

- **What.** Two buttons on the dashboard's Records card: "Download matches (CSV)", one row per match (totals, tokens, bonuses, finish times, winner, tie-break, confirmed at), and "Download cups (CSV)", one row per cup. File names `<event-slug>-matches-<date>.csv` and `<event-slug>-cups-<date>.csv`. On a shadow or test event the first column carries BETA TEST or TEST.
- **Why.** After the shadow run, the committee's paper result and Seduh Score's are compared match by match (Board plan gate G1). Q10's committee sheet has not arrived, so we propose a layout from what the app records and the owner takes it to the committee. The layout is one constant each in `scoresExport.js` (`MATCH_COLUMNS`, `CUP_COLUMNS`), so the committee's changes are a one-place edit.
- **How.** `scoresExport.js` is pure. `scoresExportData.js` reads on click only, fresh each time (no cache), from the same tables as the dashboard. Totals and tokens come from the `btc_match_scores` view and are never recomputed in the browser. Winner is the higher view total, or Level; a level knockout's tie-break gets its own two columns (from `recordedWinnerId`). A failed read throws. So does a 1000-row PostgREST cap: a truncated file would look like a result.
- **Decisions.** The cups file holds confirmed matches only. Unconfirmed matches appear in the matches file with empty score columns. The sample cups file omits Round 1 match 2 (unconfirmed), so the golden test filters it too; a reader of the sample should not take that for a bug.
- **Files.** New: `src/formats/btc/scoresExport.js`, `scoresExport.test.js`, `scoresExportData.js`. Changed: `eventDashboardScreen.js` (wiring; placeholder comment removed), `eventDashboardScreen.test.js`, `eventDashboardScreen.preview.html` (harness: both files download with the right columns and the prefix). ## v4.4.0: Organiser UX S4, the cut to the top 8 and its sign-off sheet · 2026-11-11

**Task:** Organiser UX S4 (spec U3, mockup Q8). Branch `claude/organiser-ux-s4-the-cut-8e554b`, **PR into `dev`, not merged.** **Minor** (`npm version minor`, 4.3.0 to 4.4.0): a new screen and route an organiser can use. No migration, no cloud change.

- **Scoring discipline:** rows are in the database's `btc_seeding_order`, never re-sorted. Qualifiers are seed 8 or less. The time sum is a display aid only; it never orders anyone.
- **Core:** `core/cutLine.js` (pure `describeCut`/`levelWords`, DOM `renderCutLine`); `core/signOffSheet.js`; `core/ranking.js` gains `positionsInOrder` (the numbering half of `rank()`, no sort), so the cut table cannot fork `rank()`'s numbering.

## BTC Build B part 1: the draw engine (database and pure functions, no screen) · 2026-11-09

**Task:** item B of `docs/specs/BTC-MARCH-2027-ENGINE-SPEC-DRAFT.md` (sections 4.1, 4.2, 4.4), part 1 of 2. Branch `claude/btc-b-draw-engine-6895c3` (commits `7e5553a`, `8f1955e`). **One migration, not pushed to the cloud:** `20261109100000_btc_round_draws.sql`. - **Pure draw (`formats/btc/draw.js`):** `drawRound1`, `drawRound2Random`, `drawRound2ByResults`, `assignJudges`. Each returns its pairs (`{ team1Id, team2Id }`), the seed and `warnings`. A draw is a function of the seed and the SET of teams (the list is sorted before `seededShuffle`, so a re-entered seed reproduces it whatever order the screen holds). An odd count is refused with a `DrawError` (`odd_team_count`; O1 is KIV). Rematch avoidance (default on, O5) repairs by swapping with the nearest pair, then falls back to a capped search for the fewest repeats; the reported `rematches` is always a recount. - **Database:** table `btc_round_draws` (one row per event and round: mode, seed, match count, `avoid_rematches`, `conflict_ticks`), RPC `create_btc_round(p_org_id, p_event_id, p_prelim_round, p_mode, p_seed, p_matches jsonb, p_avoid_rematches default true)` (SECURITY INVOKER, all-or-nothing, the same per-event advisory lock as the bracket functions; hints `btc_round_event_not_found`, `btc_round_exists`, `btc_prior_round_open`, `btc_round_bracket_exists`, `btc_round_incomplete`, `btc_round_matches_invalid`, `btc_round_seed_mode`, `btc_round_invalid`), and `create_btc_match` widened with an optional `p_prelim_round` (dropped and recreated, grants kept; `createMatch` passes it only when given). - **Deviations from the spec, all deliberate:** (a) a seventh argument `p_avoid_rematches`, because the spec's six had nowhere to carry the column; (b) **no UPDATE privilege on `btc_round_draws`** (select, column-level insert, delete): the record never changes after the draw, and delete is how an organiser redraws a round; (c) `conflict_ticks` is **derived by the database** from the rows (a judge and a team of the same non-null country, `match` 1-based), not claimed by the client; a conflict is never refused; (d) an unnumbered preliminary match counts as round 1; (e) matches get `created_at` 1 ms apart in draw order, because `now()` is one instant per transaction; (f) the Per-event window-lock policy was added (test `056` requires it; it is not in the CONVENTIONS tenant checklist).
- **Honest limit:** the record is organiser-asserted. A member of the owning organisation can insert or replace a draw row by hand (the insert grant covers its content columns and delete is granted).
